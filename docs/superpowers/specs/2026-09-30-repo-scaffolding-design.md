# Naren's Claude Skills: Repo Scaffolding Design

Date: 2026-09-30

## Goal

A public GitHub repo, `narens-claude-skills`, of original Claude skills that people can install and use. It is both a personal-brand showcase and a genuinely useful toolkit. This spec covers scaffolding, architecture, formatting conventions, SEO and branding. Writing the individual skills is out of scope and comes after scaffolding.

## Decisions (agreed)

- **Purpose:** personal brand and useful toolkit, equally weighted.
- **Install:** Claude Code plugin marketplace plus manual copy of a skill folder into `~/.claude/skills`.
- **Repo name:** `narens-claude-skills`.
- **Structure:** one plugin per skill.
- **Site:** README-only for launch. GitHub Pages is deferred.
- **GitHub username:** `narenDaw`, taken from local `git config user.name`. Assumption: confirm before publishing. It is used in install commands and URLs.
- **License:** MIT.

## Layout

```
narens-claude-skills/
├── README.md
├── LICENSE
├── CONTRIBUTING.md
├── CODE_OF_CONDUCT.md
├── CHANGELOG.md
├── llms.txt
├── .claude-plugin/marketplace.json
├── plugins/<skill>/
│   ├── .claude-plugin/plugin.json
│   ├── README.md
│   └── skills/<skill>/SKILL.md   (+ references/, scripts/)
├── template/                     # copy-me skill skeleton
├── scripts/                      # validate.py, build_catalog.py
├── docs/                         # conventions, specs
├── assets/                       # banner, social preview, logo mark
└── .github/                      # issue/PR templates, CI workflow
```

## Conventions

- Skill and plugin names are kebab-case; the directory name equals the `name` frontmatter.
- `SKILL.md` frontmatter requires `name` and `description`. The description is written trigger-first ("Use when ...").
- `SKILL.md` carries no branding footer, to avoid token cost on every load. Branding lives in READMEs and metadata.
- `plugin.json` and `marketplace.json` set the author/owner to `Naren`, with `homepage` and `repository` fields.
- The marketplace name is `narens-claude-skills`, so installs read `<plugin>@narens-claude-skills`.
- The root README skill catalog table is generated by `scripts/build_catalog.py` from plugin metadata, so it cannot drift.
- `scripts/validate.py` checks frontmatter, naming, that every plugin is listed in `marketplace.json`, and that the catalog is current. CI runs both scripts on every PR.

## SEO and branding

**GitHub level**
- Description (about 150 chars): "Naren's Claude skills: unique, installable Agent Skills & Claude Code plugins for developers. One-command install via plugin marketplace."
- Topics: claude, claude-code, claude-skills, agent-skills, anthropic, ai-agents, claude-code-plugins, claude-code-skills, prompt-engineering, llm, developer-tools, ai-tools, plugin-marketplace, skill-md, productivity, automation.
- Social preview: 1280x640 image with "Naren's Claude Skills", a tagline and a skill count. It is authored as SVG and exported to PNG.

**Root README (landing page), in order**
1. H1 "Naren's Claude Skills", banner with descriptive alt text, badges (license, skill count, stars).
2. One-sentence tagline containing "Claude Code", "Agent Skills" and "plugins".
3. Install: marketplace command and manual copy.
4. Generated catalog table (name, what it does, install command).
5. "Why these skills" (3-4 sentences).
6. Footer: "Made by Naren" with GitHub link and star call to action.
Keywords appear naturally in headings and prose, without stuffing.

**Per-skill README** (`plugins/<skill>/README.md`)
- Keyword-rich H1, a "when it triggers" section, a before/after example, the install command. Each page is its own search entry point.

**Visual identity**
- One accent color, an "N" monogram, and a single banner template reused across skills.

**Extras**
- `llms.txt` at the root lists the skills for AI crawlers.
- Awesome-list submissions after launch.

## Components and boundaries

| Unit | Purpose | Depends on |
|---|---|---|
| `template/` | Starting point for a new skill | none |
| `scripts/validate.py` | Enforce conventions | plugin files, marketplace.json |
| `scripts/build_catalog.py` | Generate README catalog and llms.txt entries | plugin.json files |
| `.github/workflows` | Run both scripts in CI | scripts |
| `plugins/<skill>/` | Self-contained, installable skill | none |

## Error handling and testing

- `validate.py` exits non-zero with a message naming the offending file and rule.
- The scripts are tested with small fixture plugins: one valid, and one per failure rule.
- A scaffold smoke test confirms `template/` passes `validate.py` once copied and renamed.

## Out of scope

- Writing real skills (next phase, each with its own cycle).
- GitHub Pages site.
- Creating or pushing the remote GitHub repository. This is done only on explicit request.
