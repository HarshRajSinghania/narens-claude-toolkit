## Global Constraints

- Scope is option 1: rename plus type-aware tooling and conventions. No scaffold scripts or templates for mods or servers.
- Skills and mods are plugins in `plugins/<name>/`. MCP servers live in `servers/<name>/`, are not plugins, and are not listed in `.claude-plugin/marketplace.json`.
- Type detection is by contents, never by a declared field; do not add a type field to `plugin.json`.
- `docs/superpowers/**` is history: do not rewrite any existing file there.

- `README.md` catalog and `llms.txt` are generated by `python scripts/build_catalog.py`, never hand-edited between the markers.

**Clarifications decided in this plan** (spec details the plan makes precise):

- `plugin_kinds` calls a plugin a **skill** when its `skills/` folder contains at least one directory (not when `SKILL.md` exists), so a skill directory missing its `SKILL.md` is still reported with the specific `skills/<n>/SKILL.md: missing` error.
- `hooks.json` `modules` must be a **non-empty** list of non-empty strings.
- The handoff order is rename, then update `origin`, then push (so the new README badge and links resolve the moment they are public), not push then rename. Task 1 edits the spec to say so.

## Review Focus

Failure modes the spec implies but a first pass is likely to skip. Each has a test in the task that owns the code:

1. A plugin with a `skills/` folder holding only a file, a `hooks/` folder with no `hooks.json`, or an empty `modules` list is "neither kind" or a bad mod, with the message naming the problem. (Task 2)
2. `hooks.json` problems that only fail at load: a module path that is a directory, an empty-string entry, a non-string entry; and a `hooks.json` or server README with a BOM and CRLF must still pass. (Task 2)
3. A plugin that is both a skill and a mod: errors from each half are reported, and it appears in both catalog tables. (Tasks 2 and 3)
4. Server README description edges: `>` with no space is not a description, an empty `> ` line is skipped for a later real one, CRLF works, a pipe in the description is escaped in the table, and a non-directory entry in `servers/` is ignored. (Tasks 2 and 3)
5. Old-name stragglers and stale generated files: a guard test finds the old name anywhere outside history and the migration note; the catalog check goes stale when a mod or server is added; servers are never required in `marketplace.json`. (Tasks 1, 3 and 4)

    for old, repl in PAIRS:
        new = new.replace(old, repl)
    if new != text:

            f.write(new)

print("\n".join(sorted(changed)))

def add_mod_files(plugin, modules=("register.ts",), hooks_json=None):
    """Give a plugin folder a hooks/ directory: the module files and hooks.json."""
    hooks = Path(plugin) / "hooks"
    hooks.mkdir(exist_ok=True)
    for m in modules:
        (hooks / m).write_text("export const register = () => {};\n", encoding="utf-8")
    text = hooks_json if hooks_json is not None else json.dumps({"modules": [f"./{m}" for m in modules]})
    (hooks / "hooks.json").write_text(text, encoding="utf-8")


def write_mod(root, name, **kw):
    """A mod plugin: valid plugin.json and README, hooks/hooks.json, no skills/."""
    plugin = write_plugin(root, name, with_skill=False)
    add_mod_files(plugin, **kw)
    return plugin


def write_server(root, name, *, readme=None, manifest="package.json"):
    sdir = Path(root) / "servers" / name
    sdir.mkdir(parents=True)
    text = readme if readme is not None else f"# {name}\n\n> Does {name} things.\n"
    (sdir / "README.md").write_text(text, encoding="utf-8")
    if manifest:
        (sdir / manifest).write_text("{}\n", encoding="utf-8")
    return sdir

    lines = ["| Server | What it does | Folder |", "| --- | --- | --- |"]

        lines.append(

            f"[`servers/{n}`](servers/{n}) |"
        )
    return "\n".join(lines)

        [
            "### Skills\n\n" + render_plugin_table(groups["skills"], "Skill"),
            "### Mods\n\n" + render_plugin_table(groups["mods"], "Mod"),

# Conventions

## Layout

Three kinds of things live here, told apart by their contents (`plugin.json` has no type field):

- **Skill:** a plugin in `plugins/<name>/` with `skills/<name>/SKILL.md` (plus optional `references/` and `scripts/`).

Plugin, skill and server names are kebab-case, and a skill's directory name equals the `name` in its `SKILL.md` frontmatter.

- Frontmatter requires `name` and `description`.

`plugin.json` and `marketplace.json` set the author/owner to `Naren`. `plugin.json` also needs `version` and `description`.

Keyword-rich H1 ("<name>: a Claude Code skill by Naren"), a "When it triggers" section, install commands, and a before/after example. A server README's first `> ` line is its description in the catalog.
